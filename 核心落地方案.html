2. 合同助手页面与业务流程

入口：合同管理 → 合同台账 → 当前合同详情 → 合同助手Tab。助手固定当前合同，不提供再次输入问题的表单。合同头部展示逾期未缴、即将到期等依据标识；切换原详情Tab时保留风险标识，点击可查看来源。

指标卡为“租金应收、租金已收、逾期未缴、未到期待缴”；剩余天数在问题摘要及合同基础信息展示。租金应收取当前已载入的全周期生成账单，包含未到期记录；租金已收按账单实收对应金额核对；逾期未缴仅取应收日早于截至日且存在待收余额的租金账单。保证金单列。金额按分计算，核对关系为：租金应收 = 租金已收 + 逾期未缴 + 未到期待缴；待缴 = 逾期未缴 + 未到期待缴。当前快照无减免；生产有减免、冲减或退款时须单列相应调整项并重算。默认合同为2,151,456 = 0 + 1,075,728 + 1,075,728元。

雷达五维为“回款完成、付款及时、保证金到位、企业风险、合同变更”。为演示完整图形，默认打开“展示样例”，数值72%、68%、60%、3级、90分均为独立虚拟样例，明确标注不代表当前客户情况，不参与金额、问题判断及问数聚合。点击“原始指标”后按实际来源绘制：当前回款0%，企业风险来源不足显示待核验，其他来源不足显示—。企业风险及变更名称变化不改变其实际含义：外部风险事件不能等同违约，未取得变更记录不能视为零次变更。企业风险按已授权、已核验的有效等级计算，采用主体等级及有效事件等级的最高级，1级最低、5级最高；等级仅允许整数1—5，无有效等级不展示分值或补0。企业风险轴按等级/5绘制，越向外风险越高，各轴独立解读，不输出总信用分。

履约分析与行动建议独立于雷达分组。 底层每笔逾期租金账单形成独立问题；页面示例仅保留原第1、2、4项（超过30天汇总、第一季度、第三季度），全量账单仍保留在账单明细及汇总依据内。页面展示费用项、账期、应收日、应收、租金已收、逾期未缴及账龄。临期合同单独形成到期问题。正常轴不占据问题清单；保证金资料待核验独立列为核验事项，不计入已识别风险。所有问题默认收起，标题显示事实摘要及“逾期未缴／需优先催缴”“即将到期／需跟进安排”“保障待核验／需重点核验”等标签。点击标题展开，展示账单、分析、最终建议、建议来源和办理入口，再次点击收起。只有真实余额证明保证金不足时才能标记“保障不足”。

催缴话术模板

每张单笔问题卡都有“生成催缴话术模板”。抽屉延续旧版编辑草稿的方式，包含账单选择、阶段与欠费等级、内容类型/渠道切换、模板标题、客户与合同、单笔金额、应收日、规则来源、可编辑正文，以及复制、保存草稿、重新生成操作。

模板绑定contract_id + bill_id + stage_rule + channel + data_as_of。短信为简短提醒，电话为对话提纲，邮件含主题/对账与回复要求，书面通知含送达核验要求，法务审阅稿为内部事实及证据清单。模板只引用选中账单的金额与账期，不把全合同逾期总额作为本笔金额。未知联系人、银行账号及客户地址不补造。

切换渠道/账单时按组合保留本次编辑，重新生成恢复当前模板，保存本地草稿包含账单、阶段、渠道及正文。生成、复制、保存均不执行发送、不改变账单状态；正式发送由原系统核账、审核及既有催缴流程承接。

默认合同示例：2026年第四季度逾期41天，建议正式催告；第三季度逾期133天，建议律师函评估；第二季度224天和第一季度314天，建议诉讼/仲裁评估。各阶段使用不同动作及渠道，原始应收与逾期总额保持可复算。

验收：0/1、30/31、90/91、180/181天边界；余额为0不进入催缴；错项目、停用、过期规则不能匹配；各笔分别生成建议；切换账单模板金额不串单；短信/电话/邮件/书面格式不同；法律阶段不声称已发函或已起诉；复制保存不改变业务账单；切换保留编辑、重新生成可恢复。

4. 智能问数页面与场景

入口：经营驾驶舱 → 智能问数。左侧连续对话与流式结果，右侧历史会话。结果包含“查询数据”和“分析解读”，支持合同下钻、来源查看、重新生成和表格导出。

快捷询问展示经营收缴概览、客户欠租、项目收缴、客户合同、到期续租、年底待收；合同数量查询保留在历史业务记录及自然语言问法中。“无匹配数据、无权限示例、同比数据不足”从快捷询问移除，作为三条完整历史记录：

  • “逾期超过1亿元的合同有哪些？”：查询成功，无符合条件记录；阈值高于当前样本金额，不虚构0元经营汇总。
  • “未授权项目回款情况如何？”：未查询目标项目数据，不返回指标、数量及明细。
  • “今年收入同比增长多少？”：缺少完整可比期间，不生成增长率。

上述三条是异常状态演示会话，业务数据会话使用4家实际客户，不带模拟名称。点击历史在会话内容页恢复问题、状态说明与结果，重新生成保留旧快照。新版本独立保存本地历史，避免旧虚构客户及金额混入。

智能问数的生产范围为账号有权访问的全部资管数据；本原型仅载入5份实际合同，页面必须明确范围，不能把其统计当作系统全量605份合同。完整资产台账、空置及同比不足时如实说明；设备和多经点位仍不属于本次范围。

5. 智能体与企业AI中台分工

资管页面 → 资管后端 → 企业AI中台（BaseURL＋API）→ 资管后端校验 → 页面渲染。密钥、BaseURL、应用ID和权限均在后端处理。

合同助手优先复用单合同业务API，按需封装受控工具/MCP。必要工具为get_contract、list_rent_bills、get_receipts、get_deposit_balance、get_enterprise_risk、list_effective_changes、get_project_rules。合同身份、规则匹配、金额和日期用确定性代码完成；模型负责解释事实及生成受规则约束的建议。

问数通过已治理的AI专用视图/中间表或数仓执行。中台提取意图、指标、期间、项目、客户及分组字段；资管先进行服务端权限校验，再执行允许的查询；返回数值、图表、明细、时间和证据，由中台解释。避免模型直接面对业务全表和任意SQL。

生产所需数据：合同ID/编号/客户ID/项目ID/资源关联/状态/起止日；账单ID/费用/周期/应收日/生效状态/应收/实收/减免/待收；实际到账日及收款关联；保证金条款、到账、退还及抵扣；主体统一标识与风险事件；变更审批、生效日、版本及条款差异；项目规则查询状态、有效版本、适用条件与动作。缺失字段不补造。

交付包含业务页面、离线页面、真实快照、核心方案、18个场景、XMind及源码资料包。当前页面使用静态只读快照及本地历史/草稿，流式展示为前端模拟；未调用企业AI中台或生产写接口。开发应按以上工具、字段、规则状态及结果结构接入，正式发送、派单、续签及财务处理由原系统完成。

9. V3.5业务展示与话术核验

履约建议补充“签约企业风险信息待核验”“合同变更与账单一致性待核验”。分别给出办理人、2个工作日内的核验动作、需留存的证据及后续处理。当前真实客户未取得外部风险数据，不能虚构经营异常或司法事件；不将待核验事项计入已识别风险。保证金核验保留，临期合同切换后展示具体到期与续租建议。

角色 业务人员问法 应展示的结果与后续动作
项目管理者 目前合同履约和租金收缴情况怎么样？ 合同收缴概览、应收拆分、欠租重点、临期跟进

项目负责人 各项目租金收缴情况怎么样？ 每个项目一行，应收、已收、逾期、未到期，合计可复算

结果正文使用“欠租、收缴、续租、退租、付款安排”等业务用语，统计时点、样本覆盖与应收口径放在依据说明。未授权、无匹配数据、同比不足仍仅作为历史会话示例。原型自然语言匹配仅用于演示，上线需由中台解析意图、客户、项目、期间与分组，并由资管执行服务端鉴权和确定性计算。

新增验收：①页面一级催缴卡仅3项，企业/变更/保证金核验均可展开；②企业风险样例3级、最大5级，不出现85分；③真实企业无来源显示待核验；④项目收缴按2项目聚合且合计一致；⑤客户与欠租组合查询不串客户；⑥90天续租结果2份、剩余50天，意向不虚构。
