2. 合同助手页面与操作

2.1 页面结构

保留原合同详情的“基本与条款、财务收支台账、资产与工单、变更历史、生命周期”，追加第六个Tab“合同助手”。合同头部持续显示合同号、签约客商、项目/资源、面积、结束日期、负责人。切换Tab保持同一合同。

进入合同助手后：

  1. 资管后端校验当前合同的访问权限，获取同一时点的事实快照。
  2. 首屏展示应收、已核销、逾期未核销、剩余天数；分析期间和截至时间必须可见。
  3. 雷达独立展示五个履约维度，旁边直接显示数值，可点击查看口径和事实依据。
  4. 建议卡展示“发现什么 → 依据是什么 → 先做什么 → 谁负责”，支持跳到账单、续签清单及草稿。
  5. 隐藏合同详情底部的场景问法卡片与重复账单表；在五维指标与建议中点开依据。合同助手不提供自由输入。
  6. 合同助手自动分析，并以折叠项展示各维度事实、分析解读、行动建议和来源。范围始终锁定当前合同。
  7. 分别显示“上次分析时间”和“源数据截至”。进入时加载最后结果；重新分析生成新结果及时间，不能改变源数据时点。原型只重生成样例分析并在本地保留时间；生产才会重新取数。草稿不改变财务结果。

合同详情风险标识（本次调整）

合同助手不提供自由输入区或“发送问题”按钮。合同详情公共头部展示当前合同的风险标识，切换到基本与条款、财务收支台账等Tab后仍保留。

  • 逾期欠费：当前有效逾期余额大于0，红色标识，并显示金额。点击查看账单ID、到期日、余额与到账待分配情况。
  • 保证金不足：已取得生效应缴与有效余额，且余额不足，显示橙色标识。资料缺失时只显示“保证金资料待核验”，不计入已识别风险数量。
  • 续签准备待完成：剩余0—90天，且已配置准备清单仍有未完成项，显示橙色标识。该提示为到期管理事项，不代表违约认定。
  • 企业经营风险需关注：已获取并核验的主体风险达到业务配置等级；当前用合成样例演示。
  • 合同变更较频繁：当前合同观察期内生效变更达到示例阈值；变更本身不等于违约。
  • 无已识别风险时不显示“存在履约风险”；资料缺失也不推断为无风险。标识不改变合同原有“履约中”等生命周期状态。

点击单个标识打开该项风险详情；点击风险总数查看全部已识别项。详情包含事实、来源、截至时间和处理入口，支持跳到账单、续签清单或定位合同助手对应分析。

风险状态复用合同助手同一事实快照，随有效源数据更新后重新计算。生产响应建议增加 risk_signals[]（code、label、severity、status、detail、evidence_refs、as_of、action_type）、data_gaps[] 与快照ID；标识规则由业务服务校验，不仅依据大模型文字判断。规则未配置、分析失败或结果过期时分别显示“待分析”“分析暂不可用”或“结果待更新”，不得以空数组冒充无风险。当前静态演示始终采用固定演示快照。

验收样例：HT-A01显示5项（逾期20,000元、保证金缺口10,000元、续签准备1/3、企业风险与变更关注），进入任何合同Tab仍可见；HT-C01显示保证金资料待核验，未计为保证金不足；HT-A01完成有效核销及保障/续签补齐后，相应标识随重新分析移除；企业与变更提示仍按各自来源单独复核，而不是在保存草稿后移除。

2.2 雷达定义

前三轴为0—100%比例，后两轴为0—100演示规则映射分。越高仅表示该维度表现更好；不合成信用评级、续约概率或法律责任结论。超额收款在文本显示真实比率，绘图最多到100%。

维度 分子 / 分母 业务解释 缺失或不适用
回款完成 当前期间有效核销金额 / 同范围生效应收 看账单实际结清进度 分母0时不适用；未获取核销来源时缺失
付款及时 到期应收中、按期到账并已分配的金额 / 到期应收 看付款是否按约定节点到位 无到期应收时不适用；缺少付款日期时不计算
保证金到位 有效保证金余额 / 当前生效应缴保证金 看保证金保障缺口 条款无保证金则不适用；未取得记录则未知
主体经营 演示：(5－主体风险等级) × 20 来源为已授权企业信息；主体风险0—5级只是演示规则，需业务确认 来源缺失则未知，不能当作低风险
合同稳定 演示：max(0,100－观察期已生效变更次数×15) 当前合同版本与审批；新签合同不计本合同变更，频次不直接认定违约 无变更记录来源时未知，不能按零次

**生产口径补充：**账单未到期部分不进入“付款及时”分母。演示账单全部已到期，因此原型中到期应收与期间应收相同。日期按项目业务时区计算；“逾期”取到期日早于截至日，账单到期当天不算逾期。

雷达有缺失或不适用轴时显示“—”，保留可用轴的数值和相邻有效线段，不将缺失值补0形成完整封闭图。空状态要区分“无风险信号”“数据不足”“不适用”。

2.3 合成样例演示路径

打开HT-A01，首屏应看到：应收100,000元，已核销80,000元，逾期未核销20,000元；结束日期2026-12-31，剩余53天。

问“还有哪些账单没交费？”：展示B-A01-03，2026-10-31到期，未核销20,000元。B-A01-02虽然曾迟付10,000元，但已结清，不进入当前欠费。

问“客户说已经付过款，为什么还欠费？”：单列RC-A01-01在11月7日到账5,000元、已确认关联合同但未分配，不直接冲减逾期。若财务正式分配5,000元且来源数据更新，重新分析应显示已核销85,000元、逾期15,000元；此变化作为后端联调验收用例，当前前端演示不执行核销。

点击“生成催缴草稿”：带出合同、账单、截至日、金额与负责人；显著提示先核对5,000元待分配到账；允许编辑并保存本地草稿。实际发送需进入原业务流程确认。

点击续签：准备清单1/3，意向已确认、方案审批待推进、协议签署待推进。查看保证金：有效20,000元、应缴30,000元、缺口10,000元。

3. 智能问数页面与操作

3.1 左对话、右历史

左侧为当前会话，无项目下拉筛选，包含问题输入、识别/查询状态、流式文字、指标/图表/表格、数据依据、追问建议。右侧为历史会话列表，显示标题、范围、时间和轮次；点击恢复原问题和原结果。业务页不配置BaseURL、Key或模型参数。

首屏默认展示一组已完成的经营概览问答；输入框上方为紧凑问题气泡。右侧提供经营、合同、款项、资产、年底待回收、有权无匹配、无权、数据不足的完整样例。用户在问题中指定项目，系统解析后与授权范围取交集；不能由问题扩大权限。

3.2 一次问数的执行流程

  1. 用户提问，例如“目前哪些合同欠费，需要催缴？”
  2. 资管后端创建会话/运行记录，绑定用户、组织、授权范围与截至时间。
  3. 企业中台识别问题所需的数据域、指标、筛选条件、分组和排序；歧义时先澄清。
  4. 通过资管受控API执行结构化查询，返回事实、指标口径与来源引用。
  5. 中台基于事实生成解释并按事件流返回；数值直接引用业务结果，禁止自由重算金额。
  6. 资管后端校验结构、数值与来源，前端按固定组件展示文字、指标、图表、表格。
  7. 用户继续问“按项目分组”，继承欠费意图、截至时间、授权范围，补充分组维度。
  8. 点击合同进入该合同详情的合同助手，返回时保留会话。
  9. 服务端保存会话及已完成结果快照；右侧回看不隐式重跑。重新生成保留旧结果，产生新运行快照。

4. 数据准备清单

4.1 共用实体关系

组织/租户 → 项目 → 资产/空间；客商主数据ID → 合同签约关系 → 合同；合同 → 资产占用关系、账单 → 核销分配 → 收款流水；合同 → 保证金、催缴记录、续签记录。

一个客商可以签多份合同，一份合同可以关联多资源，同一资源可存在分时/分区合同。统计先在合同/账单粒度聚合，再连接展示维度，避免多对多关系造成金额放大。主体名称用于展示，不作为关联主键。

口径与证据 metric_code/version、unit、source_id、updated_at、as_of、query_id、数据覆盖与质量状态 结果可信、对账 P0

上线原则：先验证可获得字段，再开放相应场景。合同到期已可直接依赖合同结束日；续签完成率必须等准备项与状态来源明确。仅有合同不等于已具备准确的可租面积。

4.3 规则计算放在哪里

资管业务服务或数据服务计算金额、去重、状态、生效版本、逾期天数、日期窗口与指标。AI中台负责自然语言理解、受限查询规划、结果解释、建议编排和草稿语言生成。前端仅渲染已校验结果，不自行重算生产财务口径。规则和指标目录必须版本化，并与现有财务报表对账。

5. Agent设计与企业中台接入

5.1 系统分工

层 责任
资管前端 两入口、合同上下文、流式展示、结果组件、历史/来源/跳转、草稿预览
资管后端AI适配层 登录态与权限、会话/运行、事实快照、调用中台、事件转换、结果校验、审计、超时取消
资管业务/数据API 单合同复用现有详情API，按需封装受控工具/MCP；主数据、规则与证据定位
AI专用数据层 业务同步至专用视图/中间表或数据仓库，统一粒度与口径；问数仅面向该层，不能直接给模型业务全表
企业AI中台 配置两智能体应用，意图/参数识别、工具编排、解释、草稿、流式输出

不要求用户替换已有AI中台，不预设其产品厂商、协议或模型。BaseURL + API是既定连接方式；下文路径及事件为双方讨论用的建议适配协议，需映射到实际中台规范。

5.2 合同助手Agent工作流

输入：contract_id、scene_code（进入Tab默认overview，维度/证据入口按需分析）、as_of、period、facts_snapshot_id、用户可见字段、口径版本。场景问法是需求表达，前端不提供自由输入框。

执行：固定合同 → 读取快照 → 判断数据完整性 → 执行/引用确定性指标 → 按scene_code选择分析场景 → 引用事实给结论/建议 → 输出固定结构。

能力拆分：账单核查、付款及时性、保证金、企业经营风险、合同条款与变更、到期提醒、规则匹配、催缴/待办草稿。自动分析首屏复用同一事实快照；用户点击维度查看时复用当前快照；重新分析时重新取数。Agent不能覆盖固定contract_id。

提示词约束：只引用当前合同快照中的事实与可见来源；未提供的保证金、续签、工单等显示缺失；当前余额和历史迟付分开；建议使用“待核验/建议处理”等业务表达；返回数据ID、结论关联证据与动作类型，不能仅返回不可解析的长文字。

5.3 智能问数Agent工作流

输入：question、session_id、可用上下文、授权引用、从问题中解析并经权限校验的项目条件、期间/截至、指标目录版本。

执行：识别数据域 → 主体/指标/时间消歧 → 生成受限query_spec → 业务API校验并执行 → 空/缺失处理 → 解释结果 → 返回结果组件与证据 → 保存会话。

query_spec允许metric_code、dimension_codes、typed_filters、sort、page_size。数据API只允许注册指标和维度组合，不接受模型提交的任意SQL、任意URL或跨租户参数。跨数据域查询通过预定义关系实现。全域问数是“全部授权数据”，不是绕过组织与项目权限。

建议能力API：contract_facts、contract_bills、contract_receipts、contract_renewal、contract_collection、query_metrics、query_details、resolve_customer、get_metric_definition。实际中台可以将这些HTTP API注册为工具；不要求新增MCP。

5.4 两种取数模式

**合同助手优先模式：**资管后端调用已有业务服务，生成当前合同事实快照随请求发给中台；数据小、边界固定、容易核对。

**问数优先模式：**中台在会话中调用资管受控查询API；每次调用用短期授权引用和后端绑定范围校验。若中台暂不支持工具调用，替代为“中台返回query_spec → 资管后端执行 → 中台解释结果”的两段调用。不能把全库数据或所有合同全文一次塞进提示词。

5.5 建议接口

以下是资管对前端和中台的适配接口，不是已确认的海开中台原生接口。

调用方 → 接收方 方法与路径建议 用途
前端 → 资管 POST /api/ai/contract-assistant/runs 固定contract_id，按scene_code发起自动/场景分析，返回事件流及风险标识
前端 → 资管 POST /api/ai/analytics/sessions 新建问数会话
前端 → 资管 POST /api/ai/analytics/sessions/{id}/runs 提问/重试，返回事件流
前端 → 资管 GET /api/ai/analytics/sessions 当前用户可见历史列表，分页
前端 → 资管 GET /api/ai/analytics/sessions/{id} 重新校验权限后返回会话/快照
前端 → 资管 POST /api/ai/runs/{run_id}/cancel 取消当前运行；事件流关闭不等于中台任务已取消
资管 → 中台 POST {BaseURL}/{实际应用运行路径} app_id + inputs + conversation/context + stream
中台 → 资管数据层 POST /internal/ai/query/metrics 受限query_spec执行
中台 → 资管数据层 GET /internal/ai/contracts/{id}/facts 可选的单合同补取；带短期授权引用

前端发起问数示例：

  "as_of": "2026-11-08",

  "client_request_id": "client-generated-id"
}

后端从登录态派生tenant_id、user_id、真实授权范围；filters只能收窄该范围，不信任客户端传入的授权。

资管后端调用中台的适配输入示例：

{
  "app_id": "configured-analytics-app-id",
  "request_id": "request-001",
  "conversation_id": "platform-conversation-id-or-null",
  "inputs": {

    "scope_ref": "short-lived-authorized-scope-reference",

合同助手输入另有固定contract_id与facts_snapshot；两Agent使用不同app_id或工作流标识，由服务端配置决定。

5.6 流式事件建议

浏览器通过fetch读取POST响应的SSE流，由资管后端将中台真实事件转成统一格式。不得在前端放中台鉴权密钥。每个事件带run_id、递增seq；重复seq忽略，乱序/缺口按协议处理。

事件 载荷要点 页面用途
meta run_id、session_id、scope、as_of、period、metric_version 固定本次上下文
progress stage（understanding/querying/generating） 展示可理解的执行阶段，不展示模型内部思维链
answer_delta text增量 流式文本追加
component component_id、type、完整payload、evidence_refs 更新指标/图表/表格/建议卡
evidence source_id、record_ids、updated_at、coverage 依据抽屉
clarification fields、可选主体/口径 用户补充条件
done status、result_snapshot_id 完成，允许保存快照
error code、user_message、retryable 保留问题，展示重试
cancelled run_id、status 已取消，不标完成 
event: answer_delta
data: {"run_id":"run-001","seq":3,"text":"当前范围有4份合同存在逾期。"}

event: component
data: {"run_id":"run-001","seq":4,"component_id":"overdue-total","type":"metric","payload":{"metric_code":"rent_overdue","value":48000,"unit":"CNY"},"evidence_refs":["query-001"]}

event: done
data: {"run_id":"run-001","seq":5,"status":"completed","result_snapshot_id":"snapshot-001"}

中台若只返回文本，资管仍需通过适配层补出结构化组件；不能把Markdown正文当作可验证的财务结果。component payload需按类型白名单与JSON Schema校验；金额和证据与业务查询结果一致后展示。

5.7 配置与可靠性

服务端配置：BaseURL、鉴权方式/密钥引用、合同助手app_id、问数app_id、应用路径、协议适配版本、超时、可用工具白名单、指标目录版本。真实值由中台团队提供。

建议联调起始值：建立连接10秒、首事件30秒、总运行120秒；按实际网关限制调整。业务写操作不在Agent自动执行范围；读请求如需重试使用client_request_id去重创建运行，不默认重复执行费用或其他副作用。上游不支持取消时记录取消意图、停止页面消费并隔离迟到结果，不能宣称已取消中台计算。

历史会话存资管后端，隔离租户、用户和授权对象；中台conversation_id只作为映射。回看与导出都重新校验权限；口径版本/范围变更不能默默复用旧缓存。缓存键包含权限指纹、对象/筛选、期间、数据快照、指标/应用版本。

中台失败时可展示资管已计算的确定性指标，并标记“智能分析暂不可用”；不展示上次分析当作本次新结果。日志记录请求ID、耗时、业务错误码和工具调用，不记录不必要的合同正文或密钥。

9. 1111会议版新增落地与验收要求

9.1 行动建议遵循项目规则

合同助手先读取合同所属项目的生效催缴/预警规则，确定规则ID、版本、逾期区间和标准动作，再由AI补充执行步骤、沟通要点及证据留存。未配置时必须显示“AI建议 · 项目未配置催缴规则”，不可冒充客户制度。项目规则读取失败与未配置是不同状态，生产返回失败时不能直接走无配置分支。律师函、终止合同、调整保证金仅提供提交评估建议，由业务/法务决策。

原型：海淀科技园配置COL-HD-01样例，逾期8天匹配书面催缴；创智中心没有配置，显示AI参考建议。阶段阈值仅为演示，不代表客户真实制度。

9.2 数据结果与文字解读

问数结果明确区分“01 查询数据”和“02 分析解读”。解读只能引用已返回的事实。当前总览：创智中心逾期/应收11%，海淀科技园8.67%；全域最大单合同欠费HT-A01 20,000元，其次HT-C01 12,000元；最长逾期8天，不演示多月账龄或未来回款确定预测。

年底待回收单独使用已生成计划账单：当前逾期48,000元 + 当前未到期、年底前到期90,000元 = 138,000元。新增计划账单不合并进原期间应收500,000元；明确不同观察窗口，不能混合分母。

9.3 页面与接口新增字段

合同结果新增 analyzed_at、source_as_of、enterprise_profile、contract_changes、matched_policy、analysis_sections[]（fact/interpretation/recommendation/evidence/action）。规则响应需区分 configured / not_configured / failed，企业信息区分 available / missing / expired / failed；雷达阈值、映射与版本必须返回可核对依据，不让模型主观填分。

问数结果新增 status（success/empty/denied/missing/clarify）、data_result、insights[]、authorized_scope、resolved_filters、source_coverage。后端鉴权先于查询，不把项目是否存在、金额或数量泄露给无权用户；拒绝结果不可导出业务明细。
