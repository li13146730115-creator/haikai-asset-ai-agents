2. 合同助手页面与业务流程

入口：合同管理 → 合同台账 → 当前合同详情 → 合同助手Tab。助手固定当前合同，不提供再次输入问题的表单。合同头部展示逾期未缴、即将到期等依据标识；切换原详情Tab时保留风险标识，点击可查看来源。

指标卡为“租金应收、租金已收、逾期未缴、距合同到期”。租金应收取当前已载入的全周期生成账单，包含未到期记录；租金已收按账单实收对应金额核对；逾期未缴仅取应收日早于截至日且存在待收余额的租金账单。保证金单列。

雷达五维为“回款完成、付款及时、保证金到位、企业风险、合同变更”。当前有来源的回款比例绘制，其他来源不足显示—。企业风险及变更名称变化不改变其实际含义：外部风险事件不能等同违约，未取得变更记录不能视为零次变更。生产评分方向、分档及映射规则需业务确认，不输出总信用分。

履约分析与行动建议独立于雷达分组。 每笔逾期租金账单直接形成一个具体问题，展示费用项、账期、应收日、应收、租金已收、逾期未缴及账龄。临期合同单独形成到期问题。正常轴不占据问题清单，资料缺失集中说明。

操作流程：进入自动分析 → 列出具体问题 → 查看该笔账单 → 查看项目规则 → 生成建议事项 → 人工核账及办理 → 重新分析。上次分析时间与源数据读取时间分别呈现；刷新原型仅重新组织当前快照，不声称实时同步系统。

默认乐于竞合同直接列出4笔逾期租金：265,248.00、268,195.20、271,142.40、271,142.40元，合计1,075,728.00元，分别对应2026年四个季度。2027年未到期租金不进入逾期问题清单。城华两份合同均在2026-12-31结束，距快照日50天，需单独确认续签或退出安排。

4. 智能问数页面与场景

入口：经营驾驶舱 → 智能问数。左侧连续对话与流式结果，右侧历史会话。结果包含“查询数据”和“分析解读”，支持合同下钻、来源查看、重新生成和表格导出。

快捷询问保留经营概览、合同规模、项目回款、客户合同、年底待回收等业务问题。“无匹配数据、无权限示例、同比数据不足”从快捷询问移除，作为三条完整历史记录：

  • “逾期超过1亿元的合同有哪些？”：查询成功，无符合条件记录；阈值高于当前样本金额，不虚构0元经营汇总。
  • “未授权项目回款情况如何？”：未查询目标项目数据，不返回指标、数量及明细。
  • “今年收入同比增长多少？”：缺少完整可比期间，不生成增长率。

上述三条是异常状态演示会话，业务数据会话使用4家实际客户，不带模拟名称。点击历史在会话内容页恢复问题、状态说明与结果，重新生成保留旧快照。新版本独立保存本地历史，避免旧虚构客户及金额混入。

智能问数的生产范围为账号有权访问的全部资管数据；本原型仅载入5份实际合同，页面必须明确范围，不能把其统计当作系统全量605份合同。完整资产台账、空置及同比不足时如实说明；设备和多经点位仍不属于本次范围。

5. 智能体与企业AI中台分工

资管页面 → 资管后端 → 企业AI中台（BaseURL＋API）→ 资管后端校验 → 页面渲染。密钥、BaseURL、应用ID和权限均在后端处理。

合同助手优先复用单合同业务API，按需封装受控工具/MCP。必要工具为get_contract、list_rent_bills、get_receipts、get_deposit_balance、get_enterprise_risk、list_effective_changes、get_project_rules。合同身份、规则匹配、金额和日期用确定性代码完成；模型负责解释事实及生成受规则约束的建议。

问数通过已治理的AI专用视图/中间表或数仓执行。中台提取意图、指标、期间、项目、客户及分组字段；资管先进行服务端权限校验，再执行允许的查询；返回数值、图表、明细、时间和证据，由中台解释。避免模型直接面对业务全表和任意SQL。

生产所需数据：合同ID/编号/客户ID/项目ID/资源关联/状态/起止日；账单ID/费用/周期/应收日/生效状态/应收/实收/减免/待收；实际到账日及收款关联；保证金条款、到账、退还及抵扣；主体统一标识与风险事件；变更审批、生效日、版本及条款差异；项目规则查询状态、有效版本、适用条件与动作。缺失字段不补造。
